# OneTHU 公众号订阅插件（onethu.wechat.news）

在 OneTHU 应用内订阅微信公众号：看更新列表 → 应用内读正文（含图片）→ 让内置 AI 做概览与分类 → 生成每日重点摘要。
取数走**免登录公开通道**（不需要微信登录态、不需要公众号凭据、不经过任何第三方服务器），并实现成可插拔的 provider 层——将来要接全量历史，只需新增一个 provider，UI/存储/AI 层不动。
手上有 wechatDownload 之类工具导出的 CSV/Excel 表格时，也可以直接**导入表格**，把整段历史灌进同一个列表（见 §4.1）。

- 交付物：`plugin.js`（单文件 ES 模块，插件本体）、`test.mjs`（离线测试，全离线、不联网）、`README.md`（本文件）、`LICENSE`（MIT）
- 形态：JS 插件（webview 内同域执行，全平台形态可用；**本期只在桌面端实测，Android 未验**）
- 权限：`net:external`、`llm`、`storage`、`ui`、`css`、`nav`（**不**申请 webview / info:read / clipboard:read / notify / widget / tsinghua:sdk）

## 0. 当前状态：公众号信息获取尚未完善（重要）

本插件**已经可用**，但「把任意公众号的内容自动抓回来」这件事**没有做完**，用之前请先了解边界：

| 能力 | 现状 |
| --- | --- |
| 阅读 / 收藏 / 已读 / 未读 / AI 概览 / AI 分类 / 每日重点摘要 / 订阅管理 | ✅ 完整可用，与取数通道解耦 |
| 粘贴一篇**真实文章链接**订阅 | ✅ 可用（拿到这一篇 + 号名 + biz） |
| 页面模板 / 合集（号主自己维护的部分） | ✅ 可用（免登录公开页） |
| 自备 RSS（自建 wewe-rss / Wechat2RSS 等） | ✅ 可用（填 `rssUrls` 即接入） |
| 导入表格（CSV）——历史整段灌入 | ✅ 可用（配 wechatDownload 等导出工具） |
| 按公众号名字搜索订阅 | ⚠️ 依赖搜狗，反爬很强：短时间内连续搜索会要求验证码，命中后该通道暂停 30 分钟，其它通道照常 |
| **任意公众号的全量历史** | ❌ **未实现**。微信没有公开接口，任何能拿全量的路径都需要一份你自己的凭据（详见 §6） |

结论：现阶段请把它当成**「把你能拿到的公众号内容组织好」**的工具（列表 / 阅读 / AI / 日报 / 订阅管理），而不是「输入名字就自动同步」的爬虫。
取数层是可插拔的（`PROVIDERS` 注册表），补齐全量历史**只需要新增一个 provider**，存储 / UI / AI / 命令层一行都不用改——接入方法见 §6。

本插件只存放在 GitHub 源码仓库（见 §1），**暂未提交到 OneTHU 插件市场**。

## 2. 怎么用

### 订阅（三个入口，都在「订阅公众号」命令或页面顶部）

| 输入 | 行为 |
| --- | --- |
| 文章链接 `https://mp.weixin.qq.com/s/…` | 抓文章页取到 `__biz` 与公众号名，建立订阅，并把这篇文章收进列表 |
| 公众号名（如 `清华大学学生会`） | 走搜狗微信搜索，列出候选让你选一个（选中后从跳转页取真实链接） |
| RSS / Atom 地址 | 建一条「自备 RSS」订阅（自建 wewe-rss / Wechat2RSS 可拿到历史文章） |

同一公众号的重复订阅不会重复建（按 `__biz` / RSS 地址 / 名称归主键）。

### 页面

- 顶栏：**刷新**、**生成日报**、**AI 分类**、**订阅管理**、**网络自检**、**导入表格**；下一行是「上次更新 · 未读 N · 共 M 篇」
- 订阅筛选条：全部 / 每个订阅（带未读数与取数状态点）
- 列表（默认一次渲染 120 篇，底部「已显示 N 篇（共 M 篇）」+「显示更多」每次再放 120 篇）：标题、公众号、相对时间、来源标签、未读点；表格导入的条目还会显示「阅读 1.6万 · 赞 179 · 评论 46」（表格里带了这几列时）；行内按钮 ★ 收藏、AI 总结、复制链接、标记已读
- 阅读器（点标题进入）：正文段落 + 图片（`mmbiz.qpic.cn` 图片在应用内直接显示）、摘要、来源、图片数「含 N 张图（未识图）」、复制原文链接、AI 总结
- 订阅管理：每行可勾选启用哪些取数通道（**至少留一个**，清空会被拒绝）、单独同步、**导入表格**、暂停/启用、删除（级联清理它的文章与去重记录）

### 命令

| 命令 | 作用 |
| --- | --- |
| 刷新公众号订阅 | 全部订阅增量刷新，返回每个订阅「新增 N 篇 / 无新增」，**通道失败会直接标出是哪个通道**（如 `页面模板（页面模板无内容（该号未维护模板））`） |
| 生成公众号日报 | 取当日（无则最近 3 天 / 最近 12 篇）文章，必要时代抓正文摘录，产出 markdown 日报 = AI 导读 + 本地「分类清单」；日报按日期落库，可被收藏到「今日」 |
| 订阅公众号 | 见上表（命令带输入框） |
| 看最新一篇 | 直接给最新一篇的标题/公众号/链接/AI 摘要 |
| 导入公众号文章表格（CSV） | 粘贴 wechatDownload / Excel 导出的表格（CSV 全文，或直接在 Excel 里全选复制——制表符分隔同样支持），导进指定订阅；还没有订阅时，会按表格第一行的链接自动识别公众号并建订阅 |
| 打开公众号订阅页 | 跳到插件页 |
| 网络自检（公众号通道） | 依次探测微信文章域名、搜狗搜索页、第一个订阅的页面模板，每行给出 `HTTP 状态 · 耗时 · 判定 · cookie 有/无 · 字节数`，结果同时渲染到页面顶部（也可点顶栏「网络自检」） |

日报与单篇总结都会显示模型名；AI 关闭（`aiEnabled=0`）时只做本地分类清单，不联网调用模型。

## 3. 设置项

| key | 说明 | 默认 |
| --- | --- | --- |
| `channels` | 启用的取数通道（逗号分隔，见 §4） | `homepage,album,sogou,rss` |
| `sogouEnabled` | 搜狗通道总开关（1 开 / 0 关） | `1` |
| `sogouResolveMax` | 搜狗临时链接归一上限（每次刷新最多把几篇临时链接抓成长期链接；0=不换算） | `3` |
| `rssUrls` | 自备 RSS/Atom 源，每行一个 | 空 |
| `homepageHids` | 页面模板 `hid` 扫描范围（如 `1-6`，最多 8 个 × cid 1/2/3） | `1-6` |
| `albumIds` | 补充合集，每行「名称或biz\|album_id」 | 空 |
| `dailyBodyLimit` | 生成日报时抓正文的篇数上限（每篇前 1500 字） | `6` |
| `aiEnabled` | AI 概览/分类/日报总开关 | `1` |
| `dailyAuto` | 打开页面时自动生成当日摘要 | `0` |
| `perSubKeep` | 每个订阅保留篇数（★ 收藏的、以及表格导入的篇目永不裁剪） | `60` |
| `importMax` | 一次导入表格最多收多少篇（0=不限） | `2000` |
| `requestGapMs` | 抓取间隔（毫秒，防风控） | `500` |
| `visionEnabled` | 识图开关（**本期未接线**，见 §7） | `0` |
| `vlmBaseUrl` / `vlmApiKey` / `vlmModel` | 预留：识图模型 Endpoint / Key / 名称（未启用） | 空 |
| `historyToken` | 预留：公众号后台 token（未启用，将来接全量历史用） | 空 |

设置改动最多 15 秒生效（设置快照带 TTL，避免每篇文章都读一遍）。
## 4. 数据源：四条零凭据通道（+ 订阅时的那一篇 + 表格导入）

| 通道 id | 标题 | 请求 | 能力与前提 |
| --- | --- | --- | --- |
| `homepage` | 页面模板 | `mp/homepage?__biz=…&hid=&cid=&scene=18` → `var data` → `appmsg_list` | 零凭据；只能拿到**号主维护过页面模板**的那部分（标题/链接/时间/摘要/封面） |
| `album` | 合集 | `mp/appmsgalbum?__biz=…&action=getalbum&album_id=…&count=10&is_reverse=1&scene=173` → `js_album_item` | 零凭据；需要 `album_id`（订阅时若文章页带 `album_id_str` 会自动回填，也可在设置里手填）；单合集最多翻 5 页 |
| `sogou` | 搜狗微信 | `weixin.sogou.com` 关键词搜索 → 跳转页取真实链接 | 零凭据；按关键词搜最近文章；搜索结果里的链接是**会话临时链接**（带 `signature`，过期即废），插件会趁新鲜抓一次（上限见 `sogouResolveMax`）；只有页面能给 `sn` 时才换得成长期链接，而线上页面常不给 `sn`（公众号后台发了「阅读原文/短链」形态的文章），此时**保留临时链接并标记**，之后每次刷新抓到的新临时链接会自动续期；**已存过的篇目不再重复下载整页**（正文没变化，一篇可能几 MB），只在需要时换链接；有反爬（见 §5） |
| `rss` | 自备 RSS | 用户自备 RSS/Atom | 唯一能拿到**历史文章**的现实通道：自建 wewe-rss / Wechat2RSS 后把订阅地址填进来 |

另有 `article`（来源标签「文章页」）：订阅时粘贴的那一篇直接入库，不需要通道。

### 4.1 表格导入（`csv`，只进不出）

`csv` 是一个 `importOnly` 的 provider：它**不参与刷新**（不在订阅的 `channels` 候选里，刷新也不会调用它），只在点「导入表格」时把表格里的行合并进列表；承载它的 provider 与其它通道共用同一套去重主键（`mid_idx`）与保留规则。

- 表头认 `title,url,time,like_num,read_num,share_num,comment_count`（也认中文表头 / TSV / 无表头时按这个列序）；`time` 支持 `2024-12-06 08:35:06`（北京时间）与秒/毫秒时间戳。
- 链接会被归一：`&amp;` 还原成 `&`、`http` 升 `https`、去掉 `#wechat_redirect` 片段；不是 `mp.weixin.qq.com` 的行会被跳过并在结果里报数。
- 导入的条目带 `ext.imported` 标记，**不参与「每订阅保留篇数」的滚动淘汰**（它是用户显式导入的目录），全局 600 篇上限淘汰时也跳过它。
- 重复导入同一批是幂等的：同一 `mid_idx` 只补标题/时间/摘要/统计，不新增条目。

每条订阅的 `channels` 默认为四条全开，可在订阅管理里逐条勾选；各通道结果按主键（`mid_idx`：RSS/搜狗/合集同一篇会归一到同一主键，搜狗临时链接续期也不会产生重复条目）合并去重。

**实测（2026-10-13，校园网，Node 探针驱动真模块）**：页面模板一次刷新返回 54 条候选（跨页去重后 33 篇，带真实时间戳 `sendtime`）；搜狗按关键词解析出 5 篇，时间取自 `timeConvert('…')`；文章页正文解析出 44 段、41 张图；同一账号重复刷新「新增 0 篇」（幂等）。
**网络层（插件自带，不依赖宿主）**：宿主的 `net.fetch` 既不发 `User-Agent` 也不保存 cookie（每跳新建 reqwest client）。插件因此自己带浏览器头（Chrome UA + `Accept` + `Accept-Language` + 各站 `Referer`）并维护一个按 host 分开的内存 cookie 仓（读宿主回传的 `x-onethu-set-cookie-hops` / `x-onethu-set-cookie`，`Max-Age=0` 当作删除）。实测（2026-10-14，node:https 同 IP 对照）：**不带 UA 时搜狗直接 302 → `/antispider/`，带上 UA 后同一 IP 返回 200 + 正常结果页**——所以「搜狗要求验证码」在应用里一度是缺 UA 造成的，不是出口 IP。搜狗短时间内连续搜索仍容易触发验证码：命中时该通道暂停 30 分钟并明确提示，其它通道照常。

## 5. 失败与降级（不会因为一个通道挂掉就白屏）

| 情况 | 表现 |
| --- | --- |
| 某个通道失败 | 其它通道照跑，列表保留已有内容；订阅管理里该订阅状态点变红/黄，刷新命令与 toast 会写明是哪个通道失败 |
| 所有通道都没拿到内容 | 列表**保持不变**，提示「所有取数通道都没拿到内容（已有列表保持不变，可稍后重试或换通道）」，其余功能（阅读/收藏/AI/日报）照常 |
| 需要人机验证 | 文章页被弹到微信 POC 验证页时提示「文章打不开（微信要求人机验证）：当前网络被微信判定为异常环境（开着代理/VPN、或用机房网络时常见）」，并建议关掉代理或换网络；已在列表里的条目不受影响 |
| 搜狗临时链接过期 | 提示「文章打不开（临时链接已过期）」并说明这是搜狗结果页的会话链接（请在微信里「…」→ 复制链接，或直接按名字订阅）；已在列表里的条目可在页面顶部点「刷新」重新抓一次链接 |
| 链接不完整/已失效 | 落到「系统出错」页时提示「链接已失效或不是正文链接」，并说明正确链接长什么样（`/s/…` 或带 `__biz/mid/idx/sn`） |
| 搜狗要验证码 | 该订阅的搜狗通道暂停 30 分钟并提示，其它通道继续 |
| 表格里没有可导入的行 | 说清「共 N 行、跳过 M 行（其中 K 行不是 mp.weixin.qq.com 链接）」，不建空订阅；没有订阅又识别不出公众号时，提示先用「订阅公众号」建订阅再导入 |
| 整理文章太多 | 保留最近 `perSubKeep` 篇（★ 收藏的与表格导入的永不裁剪）；全局超过 600 篇时从最大订阅丢最旧的未收藏 |

## 6. 后续怎么把「信息获取」补完（接入方法 / 扩展点契约）

这是本插件后续开发的**唯一入口**：取数层与其余所有层（存储 / UI / AI / 命令 / 日报）完全解耦，补齐能力不需要改动它们中的任何一行。

### 6.1 三步接入

1. 写一个 provider 对象（见下面骨架）；
2. 把它放进 `plugin.js` 的 `PROVIDERS` 注册表（`FEED_CHANNEL_IDS` 由它自动派生）；
3. 要新增设置项时，在 `manifest.settings` 加一个字段（`cfg/cfgNum/cfgBool` 直接可读）。

**自动生效、不用改代码的部分**：订阅管理里出现该通道的勾选框（`FEED_CHANNEL_IDS` 驱动）、来源标签用 provider 的 `title`（`sourceLabel` 先查注册表）、刷新调度把它算进去（`discoverFor` 取 `!importOnly` 的通道）、候选与其它通道按同一主键（`mid_idx`）去重合并（`mergeCandidates`）、保留/淘汰与全局上限（`trimArticles` / `globalTrim`）、AI 与日报（只读文章表）。
导入型（只进不出、不参与刷新）的通道声明 `importOnly: true` 即可，`csv` 就是例子。

### 6.2 provider 骨架

```js
const someProvider = {
  id: "mpToken",            // 通道 id（会写进 sub.channels 与 article.source）
  title: "公众号后台",       // 界面上显示的名字（来源标签直接用它）
  needs: { biz: true },     // 声明需要订阅的哪些信息（biz / keywords / rssUrl…）
  async discover(sub, _unused, opts) {   // 返回候选文章数组
    const cur = (sub.cursor && sub.cursor.mpToken) || { begin: 0 };   // 断点续抓
    const page = await 拉一页(sub.biz, cur.begin);                    // 用 getText(url) 发请求
    sub.cursor = Object.assign({}, sub.cursor, { mpToken: { begin: cur.begin + page.count } });
    return page.items.map((it) => ({
      id: articleId(it.link, it.mid, it.idx),   // 与其它通道同一主键，跨通道不重复
      title: it.title,
      link: normLink(it.link),
      t: it.t,
      digest: it.digest || "",
      cover: it.cover || "",
      source: "mpToken",
      ext: { whatever: 1 },                     // 额外字段放这里（csv 用它存阅读/点赞统计）
    }));
  },
};
```

约定（已由测试固定，见 §9 用例清单第 17 组）：
- **禁用的通道不会被调用**：调度只跑 `sub.channels ∩ 设置开关` 的通道；
- **单个通道抛错不影响其它通道**：`discoverFor` 逐通道 catch，把错误写进 `sub.sources[].error`，界面按通道显示失败原因；
- **`sub.cursor[providerId]` 用来存断点**，由框架写回订阅表（provider 里直接改 `sub.cursor` 即可）；
- **只返回数组，不要自己写存储**：合并、去重、裁剪、事件（`lastNewAt` 等）都由 `mergeCandidates` / `refreshSub` 负责；
- **不新增权限**：网络走 `getText`（宿主 `net:external`），AI 走 `aiChat`（宿主 `llm`）。

### 6.3 接入一个新通道时必须一起补的测试

`test.mjs` 用假宿主驱动真的 `plugin.js`，加一个 provider 后至少补：候选被正确解析、与其它通道同主键时合并不新增、`cursor` 被写回、通道抛错时其它通道照常、界面出现该来源标签。

### 6.4 全量历史的几条现实路径

都要用户本人操作一次；插件本身不持有任何凭据。

1. **公众号后台接口**：`/cgi-bin/searchbiz` 取 fakeid → `/cgi-bin/appmsg` 分页取历史（真全量，需自己公众号后台的 token/cookie；有频率风控 `ret=200013`；登陆态数天失效）。设置里的 `historyToken` 就是给这条路预留的。
2. **自建 wewe-rss / Wechat2RSS**：扫码一次，拿到 RSS 地址直接填 `rssUrls`，**今天就能用**。
3. **离线导入（已实现）**：用 wechatDownload 之类的工具导出 CSV，页面「导入表格」整段灌进同一张表（`csv` provider 就是这条路；见 §4.1）。要用它拿全量历史，推荐流程：
   1. 装 [wechatDownload](https://github.com/qiye45/wechatDownload)（闭源 GUI，Win/macOS）。它拿历史靠一个「密钥」步骤：把自动复制的链接**在微信 PC 客户端里打开**，由它截获 key/uin/pass_ticket——这部分完全在插件之外，本插件不参与、也不持有任何凭据。
   2. 选目标公众号 → 导出 CSV（一个时间段一批，可反复导出）。
   3. 回到 OneTHU 插件页 →「导入表格」→ 选订阅 → 粘贴 CSV 全文（或在 Excel 里全选复制）。
   4. 重复导入同一批不会产生重复条目（按 `mid_idx` 归并）。
   注意：它的导出是 **UTF-16LE + BOM**；直接复制粘贴文本没问题（解析前会去掉 NUL 填充），若用文本编辑器另存请选 UTF-8。

注意：桌面端**没有可用的扫码窗口**（宿主 `ui.webModal` 仅 Android，`services.open` 只接受清华域名），所以路线 1 需要在别处拿到 token 再填进设置。

## 7. 识图为什么这一期没接线

- 宿主 `llm.chat(input: string)` **只接受字符串**，没有图像输入通道；插件也拿不到图片字节（`net.fetch` 返回文本，图片直连只用于 `<img src>` 展示）。
- 所以 `visionEnabled` / `vlmBaseUrl` / `vlmApiKey` / `vlmModel` 只留档不生效，界面明确标注「含 N 张图（未识图）」。
- 将来两条路：① 插件内经 `net.fetch` 调用户自备的 OpenAI 兼容 VLM（需先验证 mmbiz 图片防盗链与二进制读取）；② 在宿主/内置 OH 里加一条图像输入通道。

## 8. 隐私与数据落点

- 不持有任何微信凭据、不登录、不经过第三方服务器；只对微信公开页面发 GET（带 `requestGapMs` 间隔与串行队列）。
- 数据存插件私有 KV（宿主实现为 localStorage，键前缀隔离，卸载即清）：订阅表、每订阅文章列表（标题/链接/时间/摘要/封面/分类/要点）、已读去重表、日报、AI 缓存。**正文不落库**。
- 正文只在内存里缓存最近 8 篇；AI 只发送必要片段（标题/摘要，日报额外抓最多 `dailyBodyLimit` 篇的前 1500 字）。
- 桌面宿主不支持打开外部链接，因此阅读在插件页内完成，另提供「复制原文链接」。
